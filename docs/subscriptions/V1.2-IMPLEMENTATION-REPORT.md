## Delivered design and contracts

The [impact plan](V1.2-IMPACT-PLAN.md) contains the entity diagram and explicit source supersessions. The approved Annex A is retained verbatim in the root commercial source; the old v1.0 text remains historical. The [API/Angular handoff](V1.2-API-ANGULAR-HANDOFF.md) documents actual routes, request shapes, permissions, errors, idempotency, concurrency tokens, and breaking changes. The [release runbook](V1.2-ROLLOUT.md) covers cutover, review, reconciliation, restore and roll-forward. Frontend implementation is outside scope.

* Contract is a stable Doctor-owned paid/trial series; DoctorSubscription is an accepted period. Renewals retain ContractId; parallel contracts do not supersede one another. Effective intervals are `[start,end)` and are evaluated in queries even before lifecycle workers run.
* PracticeSubscriptionAllocation records one current allocation plus immutable closed intervals, actors and reasons. Inactive practices consume capacity. Manual IsActive is never inferred from subscription status. A contract owns its own practice and distinct active assigned Reception identity limits.
* SubscriptionAllocationSelection stores exact allocation IDs and selected Reception profile IDs in both an immutable snapshot and normalized children. Queries apply a due selection before background reconciliation. A moved selected allocation invalidates the entire stale selection, creates a review issue, and cannot be reclaimed by its former contract.
* ReservationCommercialProvenance records the accepted original allocation, contract, period, time and feature terms. The logical commitment key survives movement into archives. Original Booking Only cannot gain clinical rights after a move to Full; proven original Full can continue the existing workflow with an unrelated current contract or with none. Existing accepted direct Full walk-in ticket continuity is preserved with explicit original proof; new walk-ins after expiry remain denied.
* Mutation receipts bind actor, operation and intent. Existing Cash payment ledger idempotency remains authoritative. Doctor transaction locks serialize allocation, assignment, trial and paid mutations; RowVersion and filtered uniqueness backstop the application. SQL Server additionally rejects overlapping active/scheduled intervals in one contract.

## Authorization audit

[Current symbol inventory](V1.2-CALL-SITE-INVENTORY.csv) records file, line, symbol and source for the relevant entitlement/guard calls. Practice handlers, reservations, tickets, encounters, diagnostics, prescriptions, public discovery, finance and reporting supply the owned Practice/resource context. Generic Doctor read scopes are constrained by eligible practice/time windows before paging. Original-provenance joins preserve post-expiry linked clinical/archive rights without broadening unrelated resources. Doctor-wide operating finance writes validate every attached practice; exports retain existing permission and render-time revocation checks.

Remaining compatibility methods CurrentAsync/PendingAsync/ScheduledAsync/ActiveAsync are bounded to an unambiguous series. Singular public actions reject multiple contracts rather than selecting one. LatestEndedAsync is confined to legacy singular account command selection after that ambiguity check; it is never an entitlement or original clinical grant. Doctor-wide raw UsageAsync is retained only for the one preapproval draft and explicit disabled-by-default legacy enrollment. The onboarding draft has no active allocation and grants no operational features.

## Migration and data safety

Migration `20261105111042_CommercialContractsAndPracticeAllocations` follows the untouched foundation migration. It adds SubscriptionContracts; PracticeSubscriptionAllocations; SubscriptionAllocationSelections with retained-practice and retained-Reception children; ReservationCommercialProvenances; SubscriptionMutationReceipts; SubscriptionMigrationIssues; ContractId on periods; retained-selection snapshot on change requests. Foreign keys restrict deletion of accepted commercial history. The reservation logical origin key has no FK to the live reservation table because archiving moves that row.

Doctor-wide pending/active/scheduled uniques become contract-wide. Lifetime Doctor trial uniqueness remains. Current allocation uses a unique filtered index by Practice where ReleasedAtUtc is null. UTC and decimal column precision are explicit. `TR_DoctorSubscriptions_NoPeriodOverlap` checks active/scheduled intervals with update/hold locks; error 51063 maps to a stable conflict. Model snapshot and trigger metadata agree.

The [idempotent deployment script](sql/V1.2-MIGRATION.sql), [embedded backfill reference](sql/V1.2-BACKFILL.sql), and [read-only reconciliation script](sql/V1.2-RECONCILIATION.sql) are checked in. Backfill preserves original accepted JSON and payments, follows only verified renewal audit links, flags ambiguous origins, creates no free periods, and temporarily marks proven current legacy overruns. Down refuses representational data loss once multiple contracts or proven commitment rows exist. Production requires the separate release/migration/security review in the runbook.

## Operational limits and review gates
