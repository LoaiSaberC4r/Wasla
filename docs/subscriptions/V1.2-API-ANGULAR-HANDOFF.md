# Commercial subscriptions v1.2 API and Angular handoff

Authority: [approved closure](../../SOURCE-OF-TRUTH-SUBSCRIPTION-COMMERCIAL-ADDENDUM.md).
Base: `/api/v1`. Existing bearer authentication, stored granular permissions,
first-login, ownership, Reception assignment, consent and workflow checks still apply.
Dates are UTC ISO-8601; enum outputs are names; money is decimal EGP; RowVersion is
opaque Base64. Financial amounts and accepted features come from the server.

## Breaking changes from v1.0

| v1.0 | v1.2 | Client action |
|---|---|---|
| Mandatory registration selection | Optional paid selection; no selection creates no period | Remove required subscription step |
| Registration trial OfferCode, approval starts trial | Registration trial OfferCode rejected with `Subscription.TrialRequiresSelfActivation`; approval only gives eligibility | Show eligibility after approval and call the explicit activation action |
| One Doctor subscription | Independent stable contracts, each containing accepted periods | Keep selected contract ID separately from period ID |
| Singular Doctor GET chooses current | Singular GET works only for one contract; otherwise stable 409 `Subscription.MultipleContractsRequireSelection` | Use plural list/detail routes |
| Booking Only tiers/maximum | `monthlyUnitPrice=50`, `minimumSelectedPractices=1`; no fixed business maximum | Display N × 50 monthly; use server accepted total |
| Doctor-wide usage | Current allocations and distinct assigned active Reception IDs per contract | Show independent available seats |
| Practice creation without contract | Approved creation requires `subscriptionContractId` | Offer eligible contracts with available seats |
| Paid activation replaces old access | Activation affects its own contract only | Do not discard other cards or trial state |
| Doctor-wide change/cancel | Contract-targeted actions | Carry selected contract ID and current period RowVersion |

The legacy registration response retains its old shape: `subscriptionId` is the zero
GUID when no paid selection was supplied; `subscriptionStatus` then describes no
running entitlement and must be ignored. Read trial eligibility separately. Multipart
profile, verification documents and all healthcare identity validations are unchanged.
The bounded preapproval location route can create one inactive, unallocated onboarding
draft without a subscription. After approval, allocate that draft explicitly using
the move endpoint, with its Practice RowVersion when it has no current allocation.

## Routes

All Doctor routes below require a Doctor account and own-resource scope. List/detail
responses exclude the SuperAdmin payment ledger/history. SuperAdmin period routes
retain their existing payment/read/review permissions and period-ID semantics.

| Method/path | Permission | Request/result |
|---|---|---|
| GET `/public/commercial/catalog` | Anonymous | Existing plan/feature/readiness metadata, self-start trial definition, per-practice Booking Only price |
| GET `/doctors/me/subscriptions` | `Subscriptions.ViewOwn` | Array of contract details |
| GET `/doctors/me/subscriptions/{contractId}` | `Subscriptions.ViewOwn` | One-element array of owned contract details; 404 when not owned |
| GET `/doctors/me/subscriptions/trial/eligibility` | `Subscriptions.ViewOwn` | `{status,canActivate,durationDays,practiceLimit,receptionLimit,trial}` |
| POST `/doctors/me/subscriptions/trial/activate` | `Subscriptions.ActivateTrialOwn` | Empty body; Idempotency-Key; SubscriptionDetails |
| POST `/doctors/me/subscriptions/selection` | `Subscriptions.RequestChangeOwn` | SubscriptionSelection; Idempotency-Key; pending new contract/period |
| POST `/doctors/me/subscriptions/{contractId}/change-requests` | `Subscriptions.RequestChangeOwn` | SubscriptionMutationRequest; Idempotency-Key |
| POST `/doctors/me/subscriptions/{contractId}/cancel-at-period-end` | `Subscriptions.CancelAtPeriodEndOwn` | `{rowVersion,reason?}`; Idempotency-Key |
| GET `/doctors/me/subscriptions/{contractId}/renewal-preview` | `Subscriptions.ViewOwn` | Query productCode, planCode, billingCycle, selectedPracticeCount? |
| POST `/doctors/me/subscriptions/{contractId}/renewal-selection` | `Subscriptions.RequestChangeOwn` | SubscriptionMutationRequest with exact retainedAllocations; Idempotency-Key; no payment/activation |
| POST `/doctors/me/practices` | `DoctorPractices.ManageOwn` | Existing location/name fields plus subscriptionContractId |
| GET `/doctors/me/practices/{practiceId}/subscription-allocation` | `Subscriptions.ViewOwn` | PracticeAllocationDetails |
| POST `/doctors/me/practices/{practiceId}/subscription-allocation/move` | `Subscriptions.AllocationsManageOwn` | Target contract, continuedReceptionIds, RowVersion; Idempotency-Key |
| POST `/doctors/me/practices/{practiceId}/subscription-allocation/release` | `Subscriptions.AllocationsManageOwn` | `{rowVersion,reason?}`; Idempotency-Key |
| POST `/admin/subscriptions/{periodId}/activate` | `Subscriptions.Activate` | Existing exact Cash payment request, RowVersion, Idempotency-Key |
| POST `/admin/subscriptions/{periodId}/renew` | `Subscriptions.Renew` | Exact Cash confirmation, old period RowVersion, Idempotency-Key; successor stays in same contract |
| POST `/admin/subscriptions/{periodId}/trial-extend` | `Subscriptions.ExtendTrial` | Active trial only; positive additionalDays and mandatory reason |
| POST `/admin/subscriptions/{periodId}/change-requests/{changeId}/approve` or `/reject` | `Subscriptions.ReviewChangeRequests` | Existing period/change RowVersions, reason/payment as applicable |

Existing singular selection now also requires Idempotency-Key. Singular change/cancel
routes are deprecated and reject multi-contract ambiguity. Existing confirmed cash,
change review, legacy enrollment and trial extension routes remain explicit actions.
No automatic charge/renewal, gateway, refund, proration or frontend implementation is added.

## DTOs and examples

`SubscriptionSelection`:

```json
{"productCode":"ONLINE_BOOKING_ONLY","planCode":"BOOKING_ONLY","billingCycle":"Monthly","selectedPracticeCount":5}
```

This returns a new pending period with `priceAmount=250`, `practiceLimit=5`,
`receptionLimit=0`. Accepted terms include `monthlyUnitPrice=50`, quantity, currency,
features and catalog version. Full Platform prices/capacities/readiness remain as
approved. Annual and trial Booking Only selections, nonpositive quantities, numeric
overflow, unsupported currency/precision and disabled payment methods are rejected.
The supported quantity type is positive Int32; this is a technical representation bound.

`SubscriptionDetails` keeps its existing fields: subscription (the period), usage,
entitlements, changeRequests, payments/history (admin only), rowVersion,
pendingSubscription, nextPeriod, and doctor. A period now also has subscriptionContractId.
`SubscriptionChangeType` keeps numeric 1/2/3 and adds `Renewal=4` for persisted renewal
intents; use the dedicated renewal-selection endpoint rather than sending this category
through the legacy change-type input converter.

`SubscriptionContractDetails`:

```text
subscriptionContractId
periods: SubscriptionDetails[]
practices: {practiceId,nameAr,isActive,allocationId,rowVersion}[]
usage: {practiceCount,receptionCount}
availablePracticeSeats, availableReceptionSeats
renewalPreview: SubscriptionTerms | null
upcomingStatus: Active | ExpiringSoon | RenewalConfirmed | PendingPayment | Expired
```

Use the exact time interval to identify the effective Active/Scheduled period and the
confirmed next period. End is exclusive, including when a worker has not run. A pending
contract grants no seats. Linked practices remain associated through expiry unless
explicitly released/transferred or excluded by a paid next-period selection.
The renewal preview contains the server price and accepted target terms when an intent
exists, otherwise the current catalog's renewal terms. Show it alongside the end UTC,
linked practice names/count and upcoming status. Confirmation suppresses old paid
reminders in both the durable queue and the send-time admission check.

Practice list, detail and creation include optional `commercial`:

```text
subscriptionContractId, periodId, allocationId, planCode,
effectiveState: Unallocated | CommerciallyUncovered | Covered | InactiveManual,
nextAction: Allocate | RenewOrTransfer | ManagePractice | CompleteReadinessAndActivate,
allocationRowVersion
```

Manual IsActive is independent. Creation consumes a seat immediately while inactive.
Existing activation prerequisites remain in force. A manually disabled practice is
never enabled by renewal. An unassigned Reception account consumes no contract seat;
assigning/reactivating it rechecks each affected Full Platform contract separately.

Trial activation:

```http
POST /api/v1/doctors/me/subscriptions/trial/activate
Authorization: Bearer <Doctor token>
Idempotency-Key: doctor-trial-unique-001
Content-Type: application/json

{}
```

The result is SubscriptionDetails. Its period starts at successful command UTC and
ends exactly 20 days later. Same-key replay returns the same period without resetting
timestamps or adding an Outbox event. A different key cannot start another used trial.
An existing paid period is unaffected. The first approval never starts a period.

Transfer with an explicit retained staff choice:

```json
{"targetSubscriptionContractId":"GUID","continuedReceptionIds":["AHMED-RECEPTION-PROFILE-GUID"],"rowVersion":"BASE64"}
```

IDs are Reception profile IDs, not ApplicationUser IDs. Choose only currently active
assigned identities. Empty is valid; Booking Only requires empty. Show the current
assignment list from existing Reception APIs and destination active IDs/usage from
allocation/contract details. Distinct identities already serving the target count once.
Nonselected assignments on this practice become inactive; accounts and other practice
assignments are preserved. Source payment/period is unchanged. Use the current
allocation's RowVersion; for an unallocated draft use the Practice RowVersion.

Future renewal/downgrade selection:

```json
{
  "rowVersion":"OLD-PERIOD-BASE64",
  "targetPlanCode":"STARTER",
  "targetBillingCycle":"Monthly",
  "retainedAllocations":[
    {"practiceId":"GUID","allocationId":"CURRENT-ALLOCATION-GUID","receptionIds":[]}
  ]
}
```

For Booking Only include a positive targetPracticeCount. The new total is N × 50,
including reductions (5 → 4 means 250 → 200 for the new period). The old accepted total
and features remain until the boundary. SuperAdmin confirms the accepted intent's
exact payment; early confirmation schedules the successor at old exclusive end, late
confirmation starts at actual confirmation UTC. Exact allocation tokens prevent a
moved-away practice from being reclaimed. Noncompliant migrated contracts require an
explicit compliant selection at their first renewal.

## UI state and errors

Show separate cards for each contract, linked practice names/count, usage/capacity,
end UTC, accepted renewal price/preview and confirmed successor. Keep trial eligibility
as a separate state: available, active or used/expired. Starting a trial is a Doctor
action with no second SuperAdmin/payment step. Disable repeat submission while retaining
the same key for transport retries; an intentional additional paid contract uses a new key.

Refresh RowVersions after 409; preserve the user's explicit staff/practice selections
for review before retry. Never infer a target contract from whichever card happens to
be first. Idempotency is actor/operation/resource/intent-bound; a reused key for another
intent conflicts. Replays do not repeat commercial mutations and still return current
authorized resource state. Base permission/scope revocation remains effective.

Common localized Result/ProblemDetails codes include:

```text
Subscription.MultipleContractsRequireSelection
Subscription.TrialRequiresSelfActivation
Subscription.TrialAlreadyUsed
Subscription.DoctorNotApproved
Subscription.ContractSelectionRequired
Subscription.ContractCapacityReached
Subscription.ReceptionCapacityReached
Subscription.TargetSubscriptionNotActive
Subscription.PracticeCommerciallyInactive
Subscription.PracticeUnallocated
Subscription.AllocationConflict
Subscription.StaleRowVersion
Subscription.IdempotencyConflict
Subscription.PaymentAlreadyRecorded
Subscription.PaymentAmountMismatch
Subscription.MigrationRequiresAllocationSelection
Subscription.OriginalEntitlementNotProven
Subscription.PriceOverflow
```

Authentication failures use 401, authorization 403, hidden/not-owned resources 404,
capacity/concurrency/idempotency/ambiguous selection 409, and validation uses the
existing 400/422 conventions. No response or error exposes patient clinical data.

Historical confirmed Full Platform reservations retain only their original permitted
workflow through the same owned resource chain. A Booking Only origin cannot gain
clinical rights through transfer or another active contract. Already accepted Full
walk-in commitments retain their original proven workflow under the existing clinical
foundation; new walk-ins still require current scoped coverage. Patient/Guardian
privacy and global medical rights keep their independent governing checks.
