# Owner decision v3 — Portable private storage

Approved 2026-11-08 for WAS-PROD-STORAGE-01. This decision supersedes only the
host-specific absolute storage-path requirement in decision v2. All other v2
medical, privacy, governance, authorization and Production activation rules
remain unchanged. Archive and Reservation email ownership decisions are preserved.

Production private storage uses these application-relative appsettings paths:

```text
App_Data/Wasla/
  Media/
    Doctors/
    Patients/
    MedicalRecords/
  DataProtection/
    KeyRing/
  Certificates/
    Wasla-DataProtection.pfx
```

The paths resolve against `IHostEnvironment.ContentRootPath`, never the process
working directory. Shared resolution normalizes Windows and Linux separators,
rejects empty or rooted Production paths, and prevents traversal outside
`ContentRootPath/App_Data/Wasla`. Existing private-media storage keys, module
subdirectories, authorized retrieval, scanning and reconciliation remain intact.
No public Static Files mapping or direct download route exposes App_Data.

App_Data contents are excluded from Git and application build/publish artifacts.
Every hosting provider must preserve the directory across deployments. On
MonsterASP, configure the deployment process to retain App_Data. Other providers
must supply equivalent persistent directories or mounted volumes while keeping
the same relative application paths. Publishing the application does not provision
private storage or copy an existing deployment's files.

Operators must provision the directory structure, application identity permissions
and a real encryption PFX containing its private key. Its actual password remains
in Production appsettings when required. No production certificate or password is
generated by this change. Startup still requires the provisioned persistent key
ring, certificate private key, Protect/Unprotect verification, scanner health and
authenticated STARTTLS SMTP verification. Missing dependencies fail closed.

Preserve `Wasla.Phase16`, existing Data Protection purposes, the full encrypted
key ring, required decryption certificates and the stable `OpaqueEntryKey`.
Independent instances must share the same key ring and compatible certificate
material; each instance maps its relative paths to the shared persistent storage.

Back up the complete App_Data contents independently and consistently with the
database, including key-ring files and certificate recovery material. Preserve
the corresponding configuration secrets securely. Moving hosting providers
requires transferring App_Data contents and the corresponding database backup;
relative paths do not transfer stored files. Restore and verify these together
before resuming application traffic.

See the [deployment instructions](../../deploy/family-production/README.md) and
the [Master Source of Truth](../../MASTER-SOURCE-OF-TRUTH.md). Historical closure
reports retain their original observations; local tests do not establish that
Production provisioning or HTTP isolation has been verified on the real host.
