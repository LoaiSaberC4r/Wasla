# PDF and Excel export architecture

`IReportingQueryService.BuildExportAsync` applies the same definitions, scope, time window, AsOfUtc, calculations and quality as preview. `ReportExportService` assembles authorized labels/logo, renders through `IReportDocumentRenderer`, enforces byte limits, rechecks current access and appends immutable metadata audit before returning binary bytes. A report uses a server allow-listed code, never an arbitrary Razor filename, SQL fragment or client-supplied URL.

CustomerSurvey's actual `PdfService.cs`, `RazorViewRenderer.cs`, API project and `BranchTemplatesPdfReport.cshtml` were reviewed on 2026-10-29. Central packages remain RazorLight 2.3.1, PuppeteerSharp 25.10.0 and ClosedXML 0.105.1; .NET 10 and central version management are unchanged. The report template is now the physical allow-listed `Wasla.Api/Views/Templates/Report.cshtml`. The renderer contains no copies of business KPI formulas.

## PDF

- Both prescription and report PDFs use the singleton `ChromiumPdfRenderer`. It renders trusted HTML, ensures the default `BrowserFetcher.DownloadAsync()` browser cache, launches headless Chromium, creates a page, loads content with `Load` and `Networkidle0`, awaits `document.fonts.ready`, prints A4 PDF, validates its signature, and asynchronously disposes page/browser/font handles. Existing prescription/report export paths enforce byte limits. The report keeps portrait/landscape, 12/16 mm margins and page counters; prescriptions keep issued-version markings and 12 mm margins.
- The process-wide download coordinator double-checks completion under a semaphore and retains one pending download across all callers. No executable-path setting or manually installed Chrome is required. A successful download is reused; a failed attempt can retry. After a worker restart BrowserFetcher discovers its on-disk cache. Each PDF has its own disposable browser/page; the downloaded installation, rather than a live browser session, is reused.
- Puppeteer launch and content-navigation timeouts are 1,000,000 ms, matching CustomerSurvey. Wasla's outer deadline remains 45 seconds (validated 5–120), including queue/HTML/provisioning/render work; shared PDF concurrency remains 2 (validated 1–4). The download API has no cancellation token: a cancelled/timed-out caller stops waiting while the single download continues, with failures observed and logged. Retry after provisioning completes. Late browser/page/font-handle acquisitions are disposed even when the caller has left.
- CustomerSurvey parity deliberately enables `--disable-web-security`, `--allow-file-access`, `--allow-file-access-from-files`, `--no-sandbox`, `--disable-setuid-sandbox`. These disable Chromium protections and increase the impact of untrusted content. Only encoded server-generated HTML and a fixed server-owned template key are rendered. CSP, disabled page JavaScript, offline mode and request interception allow only local data images/about:blank. No arbitrary HTML, template filename or resource URL is accepted from API clients. Run the worker with minimal privileges and protect templates/cache from untrusted writers.
- Logos remain authorized single-Practice private PNG/JPEG media, maximum 1 MiB, dimensions ≤4096 each and ≤4 million pixels. Invalid logos are omitted; SVG/remote URLs remain rejected.
- API startup and Excel never trigger browser provisioning. The startup PDF probe was removed; explicit diagnostic `ProbeAsync` remains available to server callers. `/api/v1/admin/operations/exports/health` retains its permission and existing fields: `ExecutableConfigured` is now always false (legacy compatibility field), with additive `BrowserProvisioning=AutomaticDownload` and `BrowserDownloaded` metadata. `NotMeasured`/null probe fields mean no report PDF has been attempted; download completion alone never reports `Ready`. Success requires a real PDF signature and byte-limit check. Failures produce safe infrastructure codes (`HtmlRenderFailed`, `BrowserDownloadFailed`, `BrowserLaunchFailed`, `RenderUnavailable`, `RenderTimeout`, `InvalidPdf`) and controlled 503 responses. Oversized reports retain 422 `Report.ExportTooLarge`; prescription oversized errors retain their existing infrastructure mapping. Logs include failure stage/type and deployment hints, omitting HTML, medical data and raw exception messages.
- API `PreserveCompilationContext` and `CopyLocalLockFileAssemblies` plus physical template output/publish copying support RazorLight under IIS. Template discovery uses `IWebHostEnvironment.ContentRootPath/Views/Templates`; lazy engine construction keeps template failures isolated from XLSX/startup. Infrastructure compilation references are preserved. No custom web.config or additional IIS handler was added.

See [IIS deployment smoke procedure](export-runtime-iis-smoke.md) for cache ACLs, outbound HTTPS, fonts and actual Application Pool testing, and [current implementation/verification report](customer-survey-export-runtime-report.md) for executed results. Developer-machine rendering does not establish production IIS readiness.

## Excel

Seven logical worksheets: `01 Summary`, `02 Filters and Quality`, `03 Trends`, `04 Breakdowns`, `05 Details`, `06 Charts`, `07 Comparisons`. RTL applies to Arabic; headings/fills, freeze panes, AutoFilters, widths, repeated print headings, typed dates/UTC timestamps, numeric EGP and true percentage cells are set with ClosedXML. Leading-zero and formula-like references are literal quoted text, never executable formulas. Charts are local PNGs. Missing values stay blank/explicitly unavailable; no fake zero replaces unknown data. Comparison percentages and absolute percentage-point changes use appropriate numeric formatting.

## Limits and audit

Both formats: maximum366 labeled days. PDF≤5000 detail rows/15MiB. XLSX≤25000 rows/20MiB. Rejected limits return422 `Report.ExportTooLarge`; nothing is silently truncated. A stable ASCII filename contains actor, report code, period and language. Responses set MIME type, Content-Disposition, no-store and nosniff. Unknown format/report/filter is controlled; CSV is unsupported.

Downloads share the existing `reports-export` rate-limit policy:12 requests per authenticated actor per15-minute window, queue0; rejected requests return429. PDF concurrency/timeout additionally bounds browser work. Business formulas are not recalculated in the presentation layer.

Audit captures actor/role, exact Practice/Doctor scope and permission snapshot, report window, applied filters, code, format/language, outcome, failure code, byte count and actual recorded time. It contains no file body, clinical note, patient name, secret or browser path. Failures after model authorization and denied-before-release outcomes are recorded. Requests rejected before a model exists use standard API security/error logging without persisting unauthorized scope data.

Deterministic tests cover bilingual encoded HTML, seven-sheet XLSX reopening, 25,000-row/empty reports, concurrent provisioning/cancellation, failure classification, PDF signature/byte limits, reference launch/navigation options, resource disposal and measured health. API regressions preserve permissions, scope rechecks and audit behavior. Opt-in `ExportBrowserSmokeTests` uses automatic download and can render the actual published template through `WASLA_PUBLISHED_API_DIRECTORY`. It saves only synthetic Arabic/English PDF/XLSX artifacts when `WASLA_EXPORT_QA_DIRECTORY` is supplied. See the current verification report for actual outcomes rather than treating test presence as evidence of a run.
